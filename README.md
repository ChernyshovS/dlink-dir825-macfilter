# dlink-dir825-macfilter

Блокировка и разблокировка устройств домашней сети на роутере **D-Link DIR-825ACG1** одной командой или двойным кликом по ярлыку — без захода в веб-интерфейс.

Скрипты обращаются к недокументированному JSON-RPC API прошивки и правят MAC-фильтр межсетевого экрана. Фильтр действует и на Wi-Fi-клиентов, и на подключённых кабелем.

## Зачем

Штатный способ ограничить ребёнку интернет или отключить надоевшее устройство — зайти в веб-интерфейс, найти раздел, добавить правило, сохранить. Каждый раз. Здесь это одна команда, а через ярлык на рабочем столе — двойной клик.

## Требования

- Роутер D-Link DIR-825ACG1 (возможно, подойдут и другие модели на прошивке «anweb» с интерфейсом на `/admin/`)
- Windows с PowerShell 5.1 (входит в состав системы)
- Пароль администратора роутера

## Установка

1. Скачайте или клонируйте репозиторий в любую папку.
2. Выполните первичную настройку:

```powershell
powershell -ExecutionPolicy Bypass -File "путь\к\dlink-macfilter.ps1" setup
```

### Почему `-ExecutionPolicy Bypass`

По умолчанию Windows запрещает запуск PowerShell-скриптов, и без этого ключа вы получите ошибку «выполнение сценариев отключено в этой системе». Ключ разрешает выполнение **только для одного запуска** и ничего не меняет в системе — поэтому он и стоит во всех примерах ниже.

Если не хотите указывать его каждый раз, разрешите скрипты один раз для своей учётной записи (права администратора не нужны):

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

После этого команды можно писать коротко: `.\dlink-macfilter.ps1 setup`.

Если репозиторий скачан архивом с GitHub, Windows дополнительно помечает файлы как пришедшие из интернета — снимите пометку командой `Unblock-File -Path .\*.ps1`. После `git clone` такой пометки нет.

Ярлыки, которые создаёт `make-shortcuts.ps1`, работают независимо от этих настроек: нужный ключ уже зашит внутрь ярлыка.

Скрипт спросит пароль от роутера и создаст `devices.json`. Пароль сохраняется в `cred.xml`, зашифрованный средствами Windows DPAPI: расшифровать его сможет только та же учётная запись на том же компьютере. В коде и в ярлыках пароля нет.

3. Впишите свои устройства в `devices.json` — за образец возьмите `devices.example.json`:

```json
{
  "tv": "AA:BB:CC:DD:EE:01",
  "console": "AA:BB:CC:DD:EE:02"
}
```

MAC-адреса устройств можно посмотреть в веб-интерфейсе роутера: **Статистика → DHCP** или **Wi-Fi → Управление клиентами**.

## Команды

| Команда | Действие |
|---|---|
| `.\dlink-macfilter.ps1 status` | показать текущее состояние фильтра |
| `.\dlink-macfilter.ps1 block -Name tv` | заблокировать устройство |
| `.\dlink-macfilter.ps1 unblock -Name tv` | разблокировать |
| `.\dlink-macfilter.ps1 toggle -Name tv` | переключить состояние |
| `.\dlink-macfilter.ps1 dump` | сырой ответ роутера, для диагностики |

Вместо `-Name` можно указать адрес напрямую:

```powershell
.\dlink-macfilter.ps1 block -Mac AA:BB:CC:DD:EE:01
```

Адрес роутера по умолчанию `192.168.0.1`, имя пользователя `admin`. Если у вас иначе — параметры `-Router` и `-User`.

## Окно со списком блокировок

```powershell
.\show-status.ps1
```

Открывает небольшое окно: устройство, MAC-адрес и состояние. Заблокированные выделены красным, разрешённые — зелёным, вверху показан режим фильтра. Кнопка «Обновить» перечитывает данные с роутера. Окно только читает, ничего не меняет.

Тот же список текстом, без окна:

```powershell
.\show-status.ps1 -Text
```

## Белый список Wi-Fi

Второй, независимый режим: оставить доступ к беспроводной сети только заранее заданным устройствам, все остальные не смогут подключиться.

```powershell
.\wifi-whitelist.ps1 status
.\wifi-whitelist.ps1 on
.\wifi-whitelist.ps1 off
```

Список устройств — в `whitelist.json`, образец лежит в `whitelist.example.json`:

```json
[
  { "name": "laptop", "mac": "AA:BB:CC:DD:EE:01", "band": "both" },
  { "name": "phone-5ghz", "mac": "AA:BB:CC:DD:EE:02", "band": "5" }
]
```

`band` принимает `both` (по умолчанию), `2.4` или `5`. Отдельные диапазоны нужны потому, что устройство с включённой рандомизацией MAC приходит на каждую сеть со своим адресом.

### Чем это отличается от block / unblock

| | `block` / `unblock` | Белый список |
|---|---|---|
| Механизм | MAC-фильтр межсетевого экрана | MAC-фильтр Wi-Fi |
| На что действует | Wi-Fi **и** кабель | только Wi-Fi |
| Что происходит с устройством | подключено, но без интернета | не может подключиться к сети |
| Логика | запрещаем перечисленных | разрешаем только перечисленных |

Режимы независимы и не конфликтуют: они живут в разных конфигурациях роутера. Проводные устройства при включённом белом списке сохраняют доступ и управляются через `block` / `unblock`.

### Защита от самоблокировки

Wi-Fi-фильтр перекрывает и доступ к веб-интерфейсу роутера, поэтому включение отклоняется, если:

- в белом списке нет ни одного сетевого адаптера компьютера, с которого запущен скрипт;
- список пуст хотя бы для одного диапазона.

Если ваш адрес есть на одном диапазоне, но отсутствует на другом, окно подтверждения об этом предупредит. Проверки можно снять ключом `-Force`, но тогда вы рискуете потерять управление роутером.

Порядок операций выбран так, чтобы сбой не запирал сеть: сначала на оба диапазона добавляются все адреса и только последними командами включается политика. Если что-то пойдёт не так на середине, фильтр останется выключенным.

Даже при ошибке доступ восстанавливается кабелем: на LAN-порты этот фильтр не распространяется.

`off` не удаляет адреса, а лишь отключает политику — повторное включение проходит быстрее.

## Ярлыки на рабочем столе

```powershell
.\make-shortcuts.ps1
```

Создаст по ярлыку «переключить» на каждое устройство из `devices.json`, а рядом с ними:

- `Status` — окно со списком блокировок;
- `Whitelist ON` и `Whitelist OFF` — включение и выключение белого списка Wi-Fi.

Для белого списка сделаны именно два ярлыка, а не переключатель: не видя текущего состояния, легко нажать не в ту сторону и отрезать дом от Wi-Fi. Включение спрашивает подтверждение и показывает, кто сохранит доступ; выключение срабатывает сразу.

Односторонние ярлыки для устройств и произвольная папка:

```powershell
.\make-shortcuts.ps1 -Mode block
.\make-shortcuts.ps1 -Mode unblock -Folder "C:\Users\Public\Desktop"
```

В ярлык зашивается **имя устройства**, а не адрес, поэтому при смене MAC достаточно поправить `devices.json` — ярлыки пересоздавать не нужно. Пересоздать их придётся только если перенести папку: в ярлыке хранится абсолютный путь.

## Как это устроено

Прошивка «anweb» под веб-интерфейсом держит JSON-RPC API. Всё описанное ниже получено разбором JavaScript самого интерфейса, официальной документации на него нет.

| | |
|---|---|
| Эндпоинт | `POST /jsonrpc` |
| Методы | `read`, `write`, `remove`, `cmd` |
| Сохранение в флеш | `cmd` с `id: 20` либо `save: true` в запросе |
| MAC-фильтр межсетевого экрана | конфигурация `id: 74` |
| MAC-фильтр Wi-Fi | конфигурация `id: 42` |
| Выбор сети для операций с Wi-Fi-фильтром | конфигурация `id: 39` |

Wi-Fi-фильтр устроен так: политика доступа и список адресов хранятся отдельно для каждого диапазона, префикс полей — пустой для 2,4 ГГц и `5G_` для 5 ГГц. Значения `AccessPolicy`: `0` — фильтр выключен, `1` — пускать только из списка, `2` — запрещать перечисленных. Записи списка имеют вид `{ mac, hostname, active }` и добавляются с `pos: -1`.

Перед любой операцией с конфигурацией 42 нужно записать в конфигурацию 39 поле `<префикс>mbssidCur` — указатель на сеть внутри диапазона. Настройки Wi-Fi (имена сетей, пароли, каналы) лежат в конфигурации 35 и не затрагиваются.

Служебные записи делаются без сохранения во флеш, а в конце операции выполняется одна команда `cmd id: 20`. Иначе роутер считает конфигурацию изменённой и просит сохранить её вручную.

Три неочевидные детали, без которых ничего не работает:

**1. Заголовки авторизации не симметричны.** Это обычный HTTP Digest MD5 (`qop=auth`), но вызов приходит в нестандартном заголовке `anweb-authenticate`, а ответ надо отправлять в стандартном `Authorization` — плюс пометка `anweb-repeat-request: true`. Если отвечать в том же заголовке, откуда пришёл вызов, роутер молча возвращает 401.

**2. Новое правило добавляется с `pos: -1`.** Это означает «в конец списка», позицию выбирает прошивка.

**3. Нулевой элемент массива — политика по умолчанию, а не правило.** У него `mac: null`, а поле `state` задаёт режим: `false` — разрешать всё (чёрный список), `true` — запрещать всё (белый список).

Последний пункт важен для безопасности. На роутере со сброшенными настройками массив пуст полностью, и если просто дописать туда первое правило, оно займёт нулевую позицию и превратится в «запрещать всё по умолчанию» — от сети отвалятся сразу все устройства, включая ваше. Скрипт поэтому сначала явно создаёт запись политики по умолчанию и только потом добавляет правило.

## Что нужно знать перед использованием

**Блокировка — это отсутствие интернета, а не отключение от сети.** Устройство по-прежнему подключается к Wi-Fi, получает адрес по DHCP и видит соседей по локальной сети. Роутер просто не маршрутизирует его трафик. Если нужно, чтобы устройство вообще не могло подключиться к Wi-Fi, это другой фильтр — в разделе **Wi-Fi → MAC-фильтр**, здесь он не затрагивается.

**Устройства со случайными MAC-адресами блокируются ненадёжно.** Современные телефоны по умолчанию генерируют новый адрес при каждом подключении к сети, и правило перестаёт действовать сразу после переподключения. Отличить случайный адрес от аппаратного просто: если во втором бите первого октета стоит единица (то есть первый октет — `02`, `06`, `0A`, `0E`, `12`… `AE`, `DA`, `FE`), адрес локально назначенный, то есть сгенерированный. Лечится отключением рандомизации MAC в настройках Wi-Fi на самом устройстве — параметр задаётся **отдельно для каждой сети**, а не глобально.

**Защита от самоблокировки.** `block` откажется блокировать MAC, принадлежащий сетевому адаптеру компьютера, с которого запущен скрипт. Обойти можно ключом `-Force`, но тогда вы рискуете потерять доступ и к сети, и к самому роутеру.

**Ограничение попыток входа.** Роутер даёт 5 попыток ввода пароля, после чего временно блокирует авторизацию. Если пароль сохранён неверно — удалите `cred.xml` и выполните `setup` заново.

**Износ флеш-памяти.** Каждая операция записывает конфигурацию во флеш роутера. Для ручных переключений несколько раз в день это нормально, для автоматического цикла раз в минуту — нет.

**Совместимость.** API не документирован, производитель ничего о нём не обещал. Обновление прошивки может сломать скрипты.

## Проверка результата

Веб-интерфейс роутера, раздел **Межсетевой экран → MAC-фильтр**. Режим по умолчанию должен оставаться «Разрешить», а заблокированные устройства — быть в списке исключений с действием «Запретить».
