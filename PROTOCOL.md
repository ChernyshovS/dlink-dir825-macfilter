# Протокол управления D-Link DIR-825ACG1

Разбор недокументированного API прошивки «anweb». Всё описанное получено чтением JavaScript веб-интерфейса и проверено запросами к живому устройству.

**Прошивка 3.0.7**, сборка от 8 декабря 2021, аппаратная ревизия G1. На других версиях протокол может отличаться.

Официальной документации на этот интерфейс не существует. D-Link ничего о нём не обещал и вправе изменить его в любом обновлении.

---

## Как это выяснялось

Веб-интерфейс — приложение на AngularJS, его исходники отдаются без авторизации. Это и есть основной источник:

```
http://192.168.0.1/autoconf.js                     параметры сборки, включая модель
http://192.168.0.1/apps/admin/config.js            список страниц и их контроллеров
http://192.168.0.1/concat?type=js&path=admin/js_list        код приложения
http://192.168.0.1/concat?type=js&path=admin/lib_js_list    библиотеки и конвертеры данных
http://192.168.0.1/apps/admin/pages/<страница>/ctrl.lazy.js контроллер конкретной страницы
```

Файлы минифицированы, но не обфусцированы: имена функций и полей сохранены. Полезные точки входа для поиска — `somovd` (клиент JSON-RPC), `authDigest` (авторизация), `rpcs` (номера конфигураций), названия страниц из `config.js`.

## Авторизация

Схема — HTTP Digest MD5 с `qop=auth`, но с нестандартной асимметрией, на которой легко споткнуться.

**Вызов приходит в заголовке `anweb-authenticate`:**

```
HTTP/1.1 401 Unauthorized
Anweb-Authenticate: Digest qop="auth", realm="domain", nonce="6245488"
Anweb-Auth-Try-Count: 5
Anweb-Auth-Try-Count-Remain: 5
Set-Cookie: device-session-id=...
```

**Ответ отправляется в обычном `Authorization`**, плюс отметка о повторе:

```
Authorization: Digest username="admin", realm="domain", nonce="...", uri="/jsonrpc",
               response="...", qop=auth, nc=00000001, cnonce="..."
anweb-repeat-request: true
```

Отвечать в том же заголовке, откуда пришёл вызов, бесполезно — роутер молча вернёт 401.

**Вычисления стандартные по RFC 2617:**

```
HA1      = md5(username : realm : password)
HA2      = md5(METHOD : uri)
response = md5(HA1 : nonce : nc : cnonce : qop : HA2)
```

`uri` в `HA2` — путь без строки запроса. Для `POST /jsonrpc` это `md5("POST:/jsonrpc")`, для `GET /devinfo?area=...` — `md5("GET:/devinfo")`.

⚠️ **Пять неудачных попыток — временный бан.** Подбирать пароль перебором нельзя, счётчик возвращается в заголовке `Anweb-Auth-Try-Count-Remain`.

## JSON-RPC

Единственная точка: `POST /jsonrpc`. Тело — объект или массив объектов JSON-RPC 2.0.

| Метод | Параметры | Назначение |
|---|---|---|
| `read` | `id` | прочитать конфигурацию |
| `write` | `id`, `data`, `pos`, `save` | записать |
| `remove` | `id`, `data`, `pos`, `save` | удалить запись списка |
| `cmd` | `id` | команда устройству |

Команды `cmd`: **20** — сохранить конфигурацию во флеш, **6** — перезагрузка, **8** — сохранить и перезагрузить, **10** — сброс к заводским настройкам.

Пример чтения:

```json
{ "jsonrpc": "2.0", "method": "read", "params": { "id": 74 }, "id": 1 }
```

Успешный ответ содержит `result.status = 20` и `result.data`. Иной `status` означает отказ, причём поле `error` при этом может отсутствовать — проверять надо оба.

### Сохранение и флаг «конфигурация изменена»

`write` без `save: true` применяет значение, но не пишет во флеш. Роутер при этом считает рабочую конфигурацию расходящейся с сохранённой и показывает в интерфейсе требование сохранить вручную.

Разумный компромисс: промежуточные записи с `save: false`, одна команда `cmd id:20` в конце операции. Это уменьшает износ флеш-памяти и не оставляет висящего флага.

## Номера конфигураций

| ID | Содержимое |
|---|---|
| 35 | настройки Wi-Fi: сети, пароли, радио, список `mbssid` |
| 39 | курсор: какая сеть выбрана для операций с Wi-Fi-фильтром |
| 42 | MAC-фильтр Wi-Fi: политика и списки адресов |
| 74 | MAC-фильтр межсетевого экрана |
| 112 | параметры устройства |
| 258 | ограничение скорости клиентов |

## MAC-фильтр межсетевого экрана (74)

Действует на весь мост: и на Wi-Fi, и на проводные подключения. Блокирует маршрутизацию трафика, но не мешает устройству оставаться в сети и общаться с соседями по локальной сети.

`data.macfilter` — массив. **Нулевой элемент задаёт политику по умолчанию, а не правило:**

```json
{ "id": 0, "state": false, "mac": null, "enable": "DROP" }
```

`state: false` — разрешать всё (чёрный список), `state: true` — запрещать всё (белый список). Отличительный признак этого элемента — `mac: null`.

Остальные элементы — правила:

```json
{ "id": 3, "state": true, "enable": "DROP", "mac": "AA:BB:CC:DD:EE:01", "hostname": "" }
```

`state` — включено ли правило, `enable` — действие (`ACCEPT` или `DROP`).

### Подводные камни

**Новое правило пишется с `pos: -1`** — это «добавить в конец», позицию выбирает прошивка. Существующее правило перезаписывается со своей позицией в массиве.

**На устройстве со сброшенными настройками массив пуст полностью**, включая элемент политики. Если просто дописать туда первое правило, оно займёт нулевую позицию и станет политикой по умолчанию — а при `state: true` это означает «запрещать всё». От сети отвалятся сразу все устройства, включая то, с которого выполнялась настройка, и восстановление останется только через кнопку Reset.

Правильный порядок: сначала явно записать элемент политики на позицию 0, затем добавлять правила.

## MAC-фильтр Wi-Fi (42 и 39)

Действует только на беспроводных клиентов и блокирует саму ассоциацию с точкой доступа — устройство не может подключиться к сети. Проводные подключения не затрагивает.

Поля задаются отдельно для каждого диапазона, префикс — пустой для 2,4 ГГц и `5G_` для 5 ГГц:

```json
{
  "AccessPolicy": "0",      "MacFilterList":    { "max_instance": 0 },
  "5G_AccessPolicy": "0",   "5G_MacFilterList": { "max_instance": 0 },
  "MaxNumMacFilter": 0,     "SupportHotApply": true
}
```

`AccessPolicy`: **0** — фильтр выключен, **1** — пускать только перечисленных (белый список), **2** — запрещать перечисленных (чёрный список).

Записи списка:

```json
{ "mac": "AA:BB:CC:DD:EE:01", "hostname": "laptop", "active": true }
```

Добавляются с `pos: -1`, как и в конфигурации 74.

### Курсор выбора сети

Конфигурация 42 работает не с диапазоном целиком, а с **одной выбранной сетью внутри него**. Перед любой операцией нужно записать курсор в конфигурацию 39:

```json
{ "jsonrpc": "2.0", "method": "write",
  "params": { "id": 39, "data": { "mbssidCur": 1 }, "save": false }, "id": 1 }
```

Для 5 ГГц поле называется `5G_mbssidCur`. Номера сетей и их количество берутся из конфигурации 35: `mbssidNum`, `mbssid[]` с полями `SSID` и `BSSID`. Если гостевых сетей нет, номер всегда `1`.

Чтение конфигурации 39 бесполезно — она ведёт себя как приёмник команды, а не как хранилище.

### Порядок операций

Штатный интерфейс сначала устанавливает политику, затем добавляет адреса. Для белого списка это опасно: между двумя командами политика уже «пускать только из списка», а список ещё пуст — сеть закрыта для всех.

Безопаснее наоборот: сначала наполнить списки на обоих диапазонах, последними командами включить политику. Сбой на любом шаге тогда оставляет фильтр выключенным.

**Настройки Wi-Fi (конфигурация 35) при этом трогать не нужно** — там лежат пароли сетей, и записывать туда ради фильтра ничего не требуется.

## Сведения о состоянии: `/devinfo`

`GET /devinfo?area=<области через |>&need_auth=1`, авторизация та же, `HA2 = md5("GET:/devinfo")`.

| Область | Содержимое |
|---|---|
| `client` | сведения о самом запрашивающем: MAC, IP, интерфейс, SSID, диапазон |
| `version` | модель, версия прошивки, дата сборки, ревизия, серийный номер, uptime |
| `187` | список клиентов локальной сети: MAC, IP, `name` (WLAN или LAN-порт), hostname, флаги |
| `34` | аренды DHCP |
| `42` | текущее содержимое MAC-фильтров Wi-Fi |
| `64` | беспроводные клиенты |

Числовые области соответствуют номерам конфигураций. Флаг клиента `reachable` означает активность, `stale` — что устройство давно не отвечало.

Без параметра `area` возвращается ошибка `Can't find 'area' parameter`.

## Резервная копия конфигурации

Скачивание идёт через `GET /config_load`, но одного этого запроса недостаточно: интерфейс сначала выполняет подготовительный вызов, формирующий файл. Без него возвращается страница-заглушка вместо конфигурации. Этот вызов не разбирался — резервную копию проще сделать из веб-интерфейса, раздел **Система → Конфигурация**.

---

## Прочие наблюдения

Веб-интерфейс отдаёт заводские учётные данные прямо в `autoconf.js`, в открытом виде — это константы сборки прошивки, одинаковые для всех устройств модели, а не текущий пароль. При первой настройке мастер требует его сменить.

Сессия веб-интерфейса истекает через 5 минут бездействия (`logoutTime`), что заметно при отладке через браузер.

Каждая операция записи расходует ресурс флеш-памяти. Для ручных переключений это несущественно, для автоматических циклов — нет.
